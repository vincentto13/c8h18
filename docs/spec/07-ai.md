# 07 — Computer drivers

Scope: how computer-controlled crafts drive: the waypoint graph they follow, junction and charger
choices, steering and braking, evasion, the stuck check, the booster and weapon rules, the
personality bits, the influence of the difficulty level, the catch-up numbers, the autopilot that
takes over a finished human craft and the pilots of the demo race. The control values they produce
feed the same flight model as a human's keys (chapter 05); targeting is shared with humans
(chapter 06, section 2).

Units: positions in cells (8.8), angles raw 16-bit (65536 per turn, 182 raw ≈ 1°), throttle step
26/256, steering step 100 raw.

## 1. Who is driven by the autopilot

| Craft | Autopilot |
|---|---|
| computer player (slots without a human; all 8 slots in a demo race) | always, from the start signal on |
| human, after its finish | locked on for the rest of the race (chapter 04, 5.1); the keys cannot take it back |
| human, racing | never (the original's "AUTO PILOT ON/OFF" banners exist but their trigger is undocumented) |

The finished human uses every rule below except the random shortcut junction, has no personality
bits, and fires at its own effective difficulty.

## 2. The waypoint graph

Built at race start from the level entity table (entity type 9):

- sub-type 0 chains are invisible **wall vectors** (chapter 05, 3.j), not waypoints;
- every entity with sub-type ≠ 0 and a non-zero "next" link adds the link `this → next`. Points are
  placed at the entity cell's centre; a point already present at the same place is reused (it keeps
  the type of the link that created it first); a point keeps its first child. At most 200 points;
  index 0 means "none";
- when a new point is created, it is chained into a **junction** (a ring of "peer" links) with the
  first other point within 500/256 cells (1.953) that is not yet in its ring — if the new point's
  type is a junction type, or if that nearby point is of a junction type;
- each point stores the floor height under it (the recovery truck's lowering target).

| Sub-type | Meaning |
|---|---|
| 1 | normal ("slow") |
| 2 | fuel branch (junction type) |
| 3 | ammo branch (junction type) |
| 4 | shield branch (junction type) |
| 6 | shortcut branch (junction type) |
| 7 | special 1: computer brakes for 3 ticks |
| 8 | special 2: computer does not use the booster ("hold fire") |
| 9 | special 3, "fast": computer uses the booster whenever possible ("fire at will") |
| 10 | special 3b (no documented effect) |

Queries:

- **nearest(p)**: among all links a → child(a) whose two ends are both closer to p than the link's
  length, the one with the smallest perpendicular distance from p to the line; returns that link's
  child. If no link qualifies: absolute-nearest(p).
- **absolute-nearest(p)**: the closest point that has a child.
- **junction(p, type)**: the first point in p's peer ring with that type, else p.

## 3. Per-tick autopilot

The autopilot runs inside the racing action (chapter 05, section 4) instead of the keys.

```
1  first tick on the autopilot: waypoint = nearest(position); inputs 0; done for this tick
2  stuck check (3.1); if stuck: call the recovery truck; done
3  if waypoint == 0: done
4  waypoint progress (3.2)
5  evasion counters (3.3)
6  charger stop (3.4); if stopping: done
7  steering and throttle (3.5)
8  booster (3.6)
9  targeting (chapter 06, section 2)
10 close-target flag (3.3)
11 weapons (3.7)
12 charger wishes (3.4)
```

### 3.1 Stuck check

A counter starts at 0; on 0 the position is remembered; the counter counts to 50; on the 51st tick
it restarts at 1 and, if the craft moved less than 2 cells (2D) from the remembered position, it
calls the recovery truck (action 20, chapter 05) and the counter resets; otherwise the position is
remembered anew.

### 3.2 Waypoint progress

Decision distance by the measured velocity v (chapter 05, 3.g):

| v (cells per tick) | < 50/256 | < 100/256 | < 150/256 | otherwise |
|---|---|---|---|---|
| distance | 3 cells | 4 cells | 5 cells | 6 cells |

When the 2D distance to the current waypoint is below it:

1. hold-fire = (waypoint type == 8); fire-at-will = (type == 9); type 7 → brake counter = 3.
2. last waypoint = current; current = child; if 0 → absolute-nearest(position).
3. Junction choice at the new current point: wants fuel → junction(current, 2); else wants repair
   → junction(current, 4); else wants ammo → junction(current, 3); else, computers only: when the
   low two bits of `(x + row)` of the craft's 8.8 position are 0, junction(current, 6) (the
   shortcut; see Known gaps).

### 3.3 Evasion

Two counters, c1 (steering override) and c2 (brake):

- if c1 == 0, the craft is not "fast", and any attacker's running hit count (chapter 05, 3.a) is
  above 10: c1 = 22, c2 = 3;
- if c1 == 0 and the craft's "targeted close" flag is set: c1 = 23, c2 = 1;
- the "targeted close" flag is cleared; c1 and c2 decrease by 1 if > 0.

After targeting (step 10): if the computer's target is within 5 cells (2D), the computer marks
itself "close to its target" and sets the **target's** "targeted close" flag, so the target (if it
is a computer) evades on its next tick.

### 3.4 Chargers

Wishes (step 12): fuel < 3000 → wants fuel; shield < 5000 → wants repair; ammo < 3000 → wants ammo.
They steer the junction choice (3.2).

Charger stop (step 6): the wanted pad is fuel if it wants fuel, else ammo if it wants ammo, else
shield if it wants repair. If the craft is on that pad this tick: speed input −26/256 (brake),
momentum × 15/16, steering 0; each wish whose value has reached 10000 is cleared; nothing else this
tick. The wishes are also cleared by the repair reset.

### 3.5 Steering and throttle

```
if c1 < 20:
    d = signed angle from the craft's yaw to the heading of the current waypoint (raw)
    steer = (d + 22) / 32 if d < 0 else d / 32
else:
    steer = 1294 raw (a hard right turn during the first 3 ticks of an evasion)
speed input = −26/256 if c2 != 0 else +26/256
clamped = clamp(steer, −100, +100)
steering input = clamped + previous steering input / 8   if clamped >= 0
                 clamped − previous steering input / 8   otherwise
if |steering input| < 1 raw: steering input = 0
```

### 3.6 Booster

- Personality "fast": the booster upgrade is raised to at least 1 every tick.
- If the effective difficulty is not 0, the lap counter is > 0 and hold-fire is off: if fire-at-will
  or `clamped < 18` raw (any left turn or nearly straight) the **booster** trigger is pulled; else if
  `clamped >= 183` raw the speed input becomes a brake (this branch cannot happen because of the
  ±100 clamp; kept as written).

### 3.7 Weapons

Only when the lap counter is > 0 and there is a target:

- **Minigun**: when the personality is "steady fire" or `frame mod 150 < 80` (frame = the thing's
  8-bit tick counter, so 160 of every 256 ticks fire in bursts): minigun heat = 0 (computer guns
  never overheat), minigun upgrade = effective difficulty, trigger, target = the primary target.
- **Missiles**: when the lock > 80, `frame mod 9 == 0` and the target is **not** within 5 cells:
  missile upgrade = effective difficulty, trigger, target = the primary target. Every launch costs
  1666 ammo like a human's.

Writing the upgrade means a computer's weapons fire at the difficulty level whatever it collected
(and its upgrade levels are overwritten). A personality bit 2 would block firing unless "steady
fire" is set; no computer has it.

## 4. Personalities

Assigned at race start by the computer's rank among the computer players (rank = slot − number of
humans: 0 for the first computer). In a normal race ranks 0..6 are used, in a demo race 0..7.

| Rank | Spare weak targets | Fast | Steady fire | No catch-up |
|---|---|---|---|---|
| 0 | yes | yes | | |
| 1 | | | yes | yes |
| 2 | yes | yes | | |
| 3 | yes | | yes | |
| 4 | yes | | | |
| 5 | | yes | yes | |
| 6 | yes | | | yes |
| 7 | | | | |

| Bit | Effect |
|---|---|
| spare weak targets | drops a target whose shield is below 2000 (chapter 06, 2) |
| fast | catch-up base 125 (131 when in place 4..8) instead of 120; booster upgrade ≥ 1; never evades from hits |
| steady fire | minigun fires every tick at a target instead of in bursts |
| no catch-up | catch-up target is the base only (no difficulty or place term) |

## 5. Difficulty influence

Effective difficulty: chapter 04, 9.1 (0..3; in a championship `min(race number, setting)`).

| Rule | Effect |
|---|---|
| catch-up target | + difficulty × 5 / 3 (0, 1, 3, 5) unless "no catch-up" |
| weapons | minigun and missile upgrade = difficulty when firing |
| booster | not used at all at difficulty 0 |
| targeting, steering, waypoints | unchanged |

## 6. Catch-up numbers

The behind factor steps by 1 per tick towards (chapter 04, 9.2):

| Craft | Target |
|---|---|
| human | 118 + 2 × place (+10 with the supercar bonus) |
| computer | 120 + difficulty × 5 / 3 + 4 × place − 4 |
| computer, "fast" | 125 (131 in place > 3) + difficulty × 5 / 3 + 4 × place − 4 |
| computer, "no catch-up" | 120 (fast: 125 / 131) |
| finished craft | 130 |

Examples: leading computer at difficulty 3: 125; last (8th) computer at difficulty 3: 153.

## 7. Demo race pilots

All 8 slots are computers: names SCOPER, BARNSY, SHUNTLY, COPSE, MANNY, MCLALIN, MAD, ATROW, team
colour and craft type (slot + player colour / type) mod 8 / 6, personalities by rank 0..7, the
current difficulty setting. Everything else as in section 3.

## Port deviations

- None intended beyond the general ones (20 Hz tick, floating-point arithmetic).
- Port addition, crossings (chapter 01 §9.7): on a layered level waypoints may have a level, a
  waypoint is a position and a level (so two branches can share cells), a waypoint is reached only
  on its level, and the nearest-waypoint lookups (first tick, a lost or finished craft, recovery
  without a truck) take only route stretches on the craft's level, searching the few waypoints before
  and after the current one first. Levels without the addition are unchanged.

## Known gaps

- The shortcut test "(x + row) low bits zero" is a reading of the original's test on the low bits of
  the 8.8 position; the exact bits and operands were not confirmed (a PSX-based reading of it is never
  true).
- The original clamps the steering value asymmetrically; the reference uses the symmetric ±100 and
  the `(d + 22) / 32` adjustment for negative errors. The exact asymmetric clamp is not documented.
- The waypoint sub-types 1 and 10 have no documented effect.
- The trigger of the AUTO PILOT ON / OFF, AUTO REPAIR and AUTO REFUEL banners (a human-controllable
  autopilot) is not documented.
- The stuck check is described for computer players; whether it also runs for a finished human on the
  autopilot is not documented (the reference runs it for every autopilot craft).
